{"summary": "Normalization organizes tables to reduce redundancy and avoid update, insertion and deletion anomalies. A functional dependency X -> Y means each value of X determines exactly one value of Y. 1NF requires atomic values with no repeating groups. 2NF removes partial dependencies on part of a composite key; 3NF removes transitive dependencies between non-key attributes. BCNF is stricter: for every X -> Y, X must be a superkey. The worked example splits data into Student and Department tables because DeptName depends on DeptID. Denormalization adds redundancy back to speed reads, at the cost of complex updates."}
