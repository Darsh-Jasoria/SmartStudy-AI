Lecture 9: Memory Management and Virtual Memory

Part 1: Addresses and protection
- A program generates logical addresses (also called virtual addresses). The hardware that translates them into physical addresses in main memory is the memory management unit (MMU).
- Address binding can happen at compile time, load time or execution time. Execution-time binding is needed if a process can be moved in memory while it runs.
- Protection is enforced with a base register and a limit register: every address generated by a process is checked against them, and an illegal access causes a trap to the operating system.

Part 2: Contiguous allocation and fragmentation
- In contiguous allocation each process occupies one block of memory. Free blocks are called holes.
- First-fit allocates the first hole that is large enough. Best-fit allocates the smallest hole that is large enough. Worst-fit allocates the largest hole. First-fit and best-fit are usually better than worst-fit in speed and storage use.
- External fragmentation means there is enough total free memory for a request, but it is split into holes that are too small. Compaction can remove external fragmentation by moving processes together, but it is costly and works only with execution-time binding.
- Internal fragmentation means memory allocated to a process is larger than requested, so the unused space inside the block is wasted.

Part 3: Paging
- Paging removes the need for contiguous allocation. Physical memory is divided into fixed-size blocks called frames, and logical memory is divided into blocks of the same size called pages.
- A page table maps each page number to a frame number. A logical address is split into a page number and a page offset. The page number indexes the page table, and the offset is added to the frame base to get the physical address.
- Paging has no external fragmentation, but it can have internal fragmentation in the last page of a process. The average waste is about half a page per process, so a smaller page size wastes less but makes the page table larger.
- The page table is kept in main memory, so each memory reference would need two accesses, one for the page table and one for the data. This slows the system down.

Part 4: The translation look-aside buffer
- The translation look-aside buffer (TLB) is a small, fast hardware cache of page table entries. On a TLB hit the frame number is available immediately. On a TLB miss the page table in memory is consulted and the entry is loaded into the TLB.
- The effective access time depends on the hit ratio. Example: with a TLB lookup of 10 ns, a memory access of 100 ns and a hit ratio of 80 percent, the effective access time is 0.8 x 110 + 0.2 x 210 = 130 ns.
- A higher hit ratio brings the effective access time closer to the cost of a single memory access.

Part 5: Large page tables and segmentation
- A 32-bit address space with small pages needs a very large page table. A multi-level page table (hierarchical paging) pages the page table itself, so only the parts that are in use need to be kept in memory.
- Segmentation supports the programmer's view of memory as a set of logical units such as the code, the stack and the heap. A logical address is a segment number and an offset. A segment table stores the base and the limit of each segment.
- Segmentation can cause external fragmentation because segments have different lengths. An offset beyond the segment limit causes a trap, commonly seen as a segmentation fault.

Part 6: Virtual memory and demand paging
- Virtual memory lets a process run even if only part of it is in physical memory, so the logical address space can be larger than physical memory. It works because of locality of reference: programs tend to use a small set of pages at a time.
- Demand paging loads a page into memory only when it is needed. A valid-invalid bit in each page table entry shows whether the page is in memory.
- A page fault happens when a process references a page that is not in memory. The operating system finds a free frame, reads the page from disk into the frame, updates the page table, and restarts the instruction. If there is no free frame, a page replacement algorithm chooses a victim page.
- The page fault rate strongly affects performance, because a disk read is far slower than a memory access.

Part 7: Page replacement algorithms
- FIFO replaces the page that has been in memory the longest. It is simple, but it can show Belady's anomaly, where giving a process more frames increases the number of page faults. For the reference string 1 2 3 4 1 2 5 1 2 3 4 5, FIFO causes 9 faults with 3 frames and 10 faults with 4 frames.
- The optimal algorithm replaces the page that will not be used for the longest time in the future. It gives the lowest possible fault rate, but it cannot be implemented because it needs knowledge of future references. It is used as a benchmark.
- Least recently used (LRU) replaces the page that has not been used for the longest time. It approximates the optimal algorithm by looking at the past, and it does not suffer from Belady's anomaly. A hardware counter or a stack of page numbers is needed to implement it.

Part 8: Thrashing
- Thrashing happens when a process does not have enough frames for its active pages, so it spends more time paging than executing. CPU utilisation falls, and a scheduler that sees low utilisation may admit more processes, which makes the problem worse.
- The working-set model uses the pages referenced in the most recent window of references to decide how many frames a process needs. Another approach is to control the page-fault frequency: if the fault rate is too high the process gets more frames, and if it is too low frames are taken away.
- Thrashing can be limited by reducing the degree of multiprogramming or by suspending some processes.
